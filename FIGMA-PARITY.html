Design System Figma Structure Spec#

Derived from @ui-organized/react by reading every packages/react/src/components/*/X.types.ts (props), X.styles.ts (variant axes) and X.css (layer names, token bindings). Every property, value, layer name and token in this document was read out of source — none was inferred from the Figma file, and none was carried over from manifest/components.json.

First written 2026-07-26 for the 46 components of the time. Extended on 2026-08-02 with the 21 added to reach full Ark UI component parity: every primitive in Ark's Components section now has a wrapper in this library, and every one of them has a section below. Ark's Utilities (ClientOnly, FocusTrap, Presence, Format*, Environment, Locale, Highlight, Frame, Swap, DownloadTrigger, JsonTreeView) are out of scope and have no entries.

Extended again on 2026-09-25 with Chip and DataTable (from @ui-organized/react-table), and the 21 Ark-parity sections re-read against the current .types.ts, .styles.ts and .css. That pass picked up the focus-ring change from a 0 0 0 2px box-shadow to a 2 px outline at offset 0, the shared field chrome (required dot, helper, nested FieldError), and concrete px values for every size step.

Five components predate their Ark equivalents and were deliberately left hand-rolled — Pagination, PasswordInput, DateInput/DateTimeInput and the internal Calendar. DatePicker was added alongside them rather than replacing them; see its Divergences.

The short version: the Figma library should mirror the code's own vocabulary, not Figma's. Variant values are the literal code values (size=md, not Size=Medium), property names are the literal prop names (intent, not Variant), and layer names are the literal BEM element names (accordion__trigger → trigger). That is what makes Code Connect mapping a lookup instead of a translation.

0What "matching" means#

A Figma component matches its React component when all five hold:

  1. Every visual prop is a Figma property, named identically to the React prop, with values identical to the code's string union.
  2. Every non-visual prop is absent — and listed in §7 so its absence is a decision, not an oversight.
  3. Every layer name is the BEM element name stripped of its block prefix, so .card__header is a layer called header.
  4. Every visual value is bound to a Figma Variable, resolved by the rule table in §3. No raw hex, no raw px on anything the CSS tokenises.
  5. The variant matrix is ≤ 120 and its axis product is stated.

Checking a component: open its component set, compare its property panel to the component's table in §5, then expand one variant and compare the layer names.

On state=active, not pressed#

The state axis is named after the CSS pseudo-classes the components actually implement — :hover, :active, :focus-visible, :disabled. Figma's own conventions call the third one "Pressed"; this library calls it active because that is what the CSS selector is. Use active.

On lowercase values#

size=md reads worse in the Figma variants panel than Size=Medium. That cost is deliberate. md is what ButtonProps["size"] accepts, so a Code Connect mapping is size → size with no value table, and a designer reading the variant name is reading the prop they would type. Every value in §5 is copy-pasteable into JSX.

The icon rule#

iconPosition is never a variant axis. Any component whose React API accepts an icon gets two sibling slots in its layer tree:

root
├── icon-leading     INSTANCE, hidden by default
├── label            TEXT
└── icon-trailing    INSTANCE, hidden by default

Each slot gets a BOOLEAN (icon-leading / icon-trailing) controlling visible, and they share one INSTANCE_SWAP property named icon. iconPosition="left" is icon-leading=true; "right" is icon-trailing=true.

This is a deliberate divergence from React, and it is what keeps Button under the cap: intent(6) × size(3) × iconPosition(2) × state(5) = 180 becomes intent(6) × size(3) × state(5) = 90.

It is also a deliberate divergence from the current generator output. The committed generated/specs/Button.json still declares iconPosition as a VARIANT axis, and lands on exactly 120 variants — which is MAX_VARIANTS, meaning that spec is truncated and does not cover the full matrix. Build the 90-variant, two-slot form described here; it is complete, whereas 120 is a ceiling artefact.

The cap rule#

When axes still exceed 120, resolve in this order and record which rule was used:

  1. Move any icon axis to slots (above).
  2. Extract repeating children into a _Parent/Item sub-component that carries its own state axis, leaving the parent with few or no states.
  3. Only then split the set by its widest axis.

The state rule#

state is added to every component a user can interact with — anything rendering a <button>, <input>, <textarea>, or a focusable item row. It is not added to purely presentational components (Card, Divider, Skeleton, Tag, Alert, Avatar, Progress, Meter, Icon, FieldError), which have no interactive CSS.

For a given component, include only the states its CSS actually distinguishes. Every component's section lists its real state set; most inputs are default, hover, focus, disabled with no active, because pressing a text field looks like focusing it.

Track and arc are one paint in code — a conic gradient flipping colour at --angle, with the hollow punched out by a mask (the #000 in the mask is compositing, not palette). Figma cannot bind a conic stop, so build it as two ring ellipses: track as a full ring, range as an arc from 0° (twelve o'clock) sweeping clockwise to the value. Both use Figma's ellipse ratio (inner radius 75%, i.e. 1 − 2/8) so the band stays one eighth of the diameter.

The knob does not rotate with the thumb. The thumb is only a positioner; the knob is counter-rotated so its drop shadow stays below it rather than orbiting the dial. In Figma, rotate the thumb frame about the dial centre and counter-rotate knob by the same angle. The focus ring sits on thumb, outside the knob and its shadow.

The label is inside the dial, not above it: this component does not use .field__label. error folds into state=invalid, and its string shows in a nested FieldError while helper hides.
